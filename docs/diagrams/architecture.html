ap-explanation architecture

What this view shows

settings.py is not drawn: 7 modules import it and it imports nothing from the service. The import cycle between di.py and celery_app.py is gone.

  1. Three connections to open one. find_database connects to check the database, create_connection_pool connects again for the same check, then the pool opens. The second check can go; the pool stays.
  2. QueryRepository still does three jobs. Running queries, guarding them (_check_aggregated_rows, _reserve, _apply_limits) and dumping the schema for the LLM (get_schema_definition).
  3. Two tasks, one plumbing. tasks/maintenance imports the private _run_in_thread from tasks/explain, and both build the explain_lock:{db} key.
  4. Migration code in AnnotationRepository. Most of add_semiring handles per-semiring and ctid tables from earlier versions. It can go once every database has been annotated again.
  5. Seeding lives in types. DataSource.seed_database runs SQL, so the domain types depend on psycopg.
  6. Protocols with one implementation. LockProvider and CacheProvider have only their Redis class, and get_lock_provider / get_cache_provider only return a module global.
  7. Unused code. get_semirings, CacheProvider.delete, exchange_token and _exchange, and the remove_annotation chain.
